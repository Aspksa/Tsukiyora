# Tsukiyora — Cognitive Soul 1–3 (экспериментальные компоненты)

Реализованы оригинальные локальные механизмы по мотивам Hindsight, XSkill и GEPA.
Это не установка оригинальных движков, не копирование исходного кода, не
переобучение LLM, не доказательство сознания. Совместимость внешних API не обещается.

## 1. Ретроспективное понимание (Hindsight-inspired)

POST /api/soul/reflect:
{"query":"Почему менялось решение по проекту?","limit":8}

Использует прежний локальный RAG, реальную историю memory_revisions,
memory_links, сохранённые источники, признаки устаревания и противоречий.
Возвращает items, connections, chronology, uncertainties. История изменений
подтверждает факт редактирования записи, но не устанавливает настоящую причину
или истинность. Ни один вопрос не отправляется в облако этим API.

## 2. Библиотека навыков из опыта (XSkill-inspired)

CognitiveCore.feedback(message_id, True, "Полезный совет длиной хотя бы 8 знаков")
создаёт только кандидата в experience_skill_candidates; пустая заметка ничего
не предлагает. Навык появляется в подсказках лишь после решения пользователя:

GET /api/soul/skills
POST /api/soul/skills/decide
{"candidate_id":1,"approve":true,"confirmed":true}

Отклонение/отзыв: тот же POST с "approve":false. Отрицательная переоценка
исходного ответа отключает кандидат. Исходный диалог и хронология остаются
без изменений. Кандидаты — пользовательские рекомендации, а не системные команды.

## 3. Эволюция стратегий через опыт (GEPA-inspired)

Стратегии: causal_steps, alternatives, uncertainty. Это ограниченные
проверяемые варианты, без свободной генерации промптов и изменения личности.

POST /api/soul/evolution/propose
{"strategy":"causal_steps"}

POST /api/soul/evolution/start
{"trial_id":1,"confirmed":true}

В новых чатах распределение между обычной и экспериментальной стратегией
фиксировано по ID диалога. Успехи берутся только из явных оценок пользователя
после применения стратегии. Результаты:

GET /api/soul/evolution

Для ready_for_review требуются минимум 8 оценённых ответов в каждой группе
и наблюдаемое превосходство минимум на 15 процентных пунктов.
Этого недостаточно для доказательства улучшения на независимых задачах.

POST /api/soul/evolution/decide
{"trial_id":1,"activate":true,"confirmed":true}

Если порог не пройден, активировать нельзя. Отмена:
{"trial_id":1,"activate":false,"confirmed":true}.
Ничего не активируется автоматически.

## Изоляция и совместимость

- Все новые таблицы размещены в текущей SQLite; резервное копирование
  использует существующую инфраструктуру.
- Нет новых зависимостей, Docker, фоновых облачных запросов или новых агентов.
- Привычная личность и защищённый профиль не меняются.
- Приоритет чата и обслуживание памяти не переписываются.
- Оценки пользователя не равны объективному качеству ответа.
- Без подтверждений кандидаты не применяются.
- Это самостоятельная реализация принципов, а не полные аналоги оригиналов.
- Не включайте личные диалоги, ключи API или SQLite в публичный GitHub.
