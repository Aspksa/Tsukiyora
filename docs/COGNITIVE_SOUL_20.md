# Tsukiyora — Cognitive Soul 2.0 (10 модулей)

Это реализация десяти **локальных проверяемых механизмов** поверх текущих
SQLite, RAG, SOUL ACADEMY, Hindsight-inspired, XSkill-inspired и GEPA-inspired
компонентов. Она не означает сознание, настоящие эмоции, человеческое понимание,
неограниченный самообучающийся ИИ или изменение весов облачной модели.

**Доступ:** Настройки → Опыт и биография → Cognitive Soul 2.0.
Тот же Python API, SQLite, HTML/CSS/TypeScript. Без Docker, Ollama, новых
зависимостей, фоновых Cloud.ru-запросов и сторонних сервисов.

## Десять возможностей

1. **Причинно-следственный интеллект:** POST /api/soul/next/causal с query
   извлекает подтверждённые воспоминания и **указанные в источнике** формулировки
   причин. Сходство или последовательность событий не считаются доказательством.
2. **Метапознание:** POST /api/soul/next/selfcheck с message_id выполняет
   локальный аудит сохранённого ответа; проверяет наличие ссылок, доступность
   записей и флаги противоречий, но не фактическую истину всех предложений.
3. **Автоматическое формирование навыков:** GET /api/soul/next/skills группирует
   повторяющиеся рекомендации из явных положительных оценок. Кандидаты
   формируются существующим ExperienceSkills, применение только после
   подтверждения (POST /api/soul/skills/decide).
4. **Понимание пользователя:** GET /api/soul/next/understanding показывает только
   подтверждённые факты, предпочтения, события и явно заявленные цели.
   Не строит психопортрет и не угадывает скрытые намерения.
5. **Рабочая модель внутреннего состояния:** GET /api/soul/next/state считает
   активные задачи, ожидающие проверки записи и вопросы, количество оценок
   и последнее локальное обслуживание. Это наблюдаемая нагрузка, не чувства.
6. **Интеллектуальное любопытство:** POST /api/soul/next/gap выявляет
   недостаточные сведения. POST /api/soul/next/question/save сохраняет
   вопрос только при confirmed:true; GET /api/soul/next/questions показывает
   очередь; POST /api/soul/next/question/decide одобряет/отклоняет.
   Одобрение не запускает интернет-исследование автоматически.
7. **Мысленные эксперименты:** POST /api/soul/next/scenario с decision,
   option_a и option_b сравнивает два варианта, предложенных пользователем,
   и указывает пробелы в доказательствах. Не выдумывает вероятности.
8. **Самоисправляющаяся память:** POST /api/soul/next/memory/review возвращает
   сигналы дубликатов, противоречий и устаревания. Никакие записи не удаляются
   и не исправляются без отдельного подтверждения в существующем интерфейсе.
9. **Эволюция личности:** GET /api/soul/next/personality связывает только
   реальные подтверждённые привычки, одобренные навыки и хронологию
   программного профиля; защищённый soul/personality.json не переписывается.
10. **Когнитивный симулятор:** POST /api/soul/next/simulate с strategy, skill,
    answer и confirmed:true выполняет ограниченную локальную проверку текста
    по контрольному заданию. Хранится только SHA-256 ответа, тип теста,
    бинарный результат и проверенные правила; исходный ответ не сохраняется.
    Это smoke-test, **не запуск реальной модели** и не подтверждение
    эффективности промпта. GET /api/soul/next/simulations — история результатов.

## Пример работы API

    POST /api/soul/next/goal/save
    {"title":"Проверять источники договоров","confirmed":true}

    POST /api/soul/next/causal
    {"query":"Почему срок поставки изменился?"}

    POST /api/soul/next/simulate
    {"strategy":"causal_steps","skill":"accuracy",
     "answer":"Нужно проверить противоречия и источники",
     "confirmed":true}

Небезопасные и неподтверждённые изменения не запускаются.
Интерфейс использует same-origin JSON и запросы с проверкой Origin.
Персональные воспоминания, пользовательские цели и результаты не
публикуются в GitHub.

## Ограничения и дальнейшие проверки

- Проблема достоверности: источник пользовательского воспоминания не
  устанавливает факт объективной истины.
- Ретроспективный поиск и причинность ограничены локальными записями и
  эвристиками. Нет причинных экспериментов, симуляции реального мира
  и автоматического научного исследования.
- Текстовые упражнения не оценивают модель и не доказывают успешность её
  обучения; реальная проверка требует независимых тестовых задач и ручного
  согласия на использование Cloud.ru.
- Сканирование потенциальных дубликатов ограничено частями SQLite;
  отсутствие предупреждения не доказывает отсутствие противоречий.
- Автоматические подсказки не получают права на самоизменение исходников,
  запись новых предпочтений или смену личности.
- Все пользовательские данные и SQLite хранятся локально в data/;
  ключ Cloud.ru в GitHub не помещать.
- Система работает в фоновом режиме только при запущенном сервере;
  новые 10 функций вызываются пользователем или читают уже накопленные
  результаты обслуживания.

## Проверка

    python -m unittest discover -s tests -v
    python launcher.py --self-test

GitHub Actions проверяет Windows/Linux, BAT self-test на Windows и SQLite
нагрузку на миллион строк. Реальную доступность Cloud.ru может подтвердить
только проверка с пользовательским ключом.
