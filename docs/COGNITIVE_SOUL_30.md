# Cognitive Soul 3.0 — проверяемое интеллектуальное самоулучшение

Это ограниченная система улучшения стратегий ответов, а не самопереписывание
исходного кода, тренировка нейросети или доказательство сознания.

## Цикл

1. Наблюдение: при повторных отрицательных оценках одной категории
   появляется неактивная гипотеза из трёх известных стратегий.
2. Гипотеза: causal_steps, alternatives, uncertainty. Свободные промпты
   не создаются, защищённый профиль не изменяется.
3. Подготовка: пользователь сохраняет минимум четыре независимых
   контрольных вопроса (split=holdout) с краткими эталонными ответами.
4. Проверка: пользователь подтверждает 8 потенциально платных запросов
   Cloud.ru (baseline/кандидат на каждом из 4 одинаковых заданий).
   Правильные ответы не отправляются модели. Используется выбранная модель
   и существующие дневные/минутные лимиты.
5. Метрики: нормализованное строгое совпадение ответа с эталоном, доли
   успеха, регрессии, длительность и число вызовов.
6. Решение: минимум четыре пары, наблюдаемый выигрыш 25 п.п. и ни одной
   регрессии — порог для ручного одобрения. Никакой автоматической активации.
7. После активации сохраняется ссылка от ответа к одобренной стратегии.
   При минимум 8 оценках и полезности не выше 25% стратегия автоматически
   отключается. Ручной откат может восстановить прежнюю версию.

## Чего этот этап НЕ доказывает

- Совпадение на 4 коротких заданиях не означает общий рост интеллекта.
- Эталон вводит пользователь; его истинность не устанавливается автоматически.
- Повторное использование тех же вопросов увеличивает риск переобучения
  стратегий на бенчмарке. Нужны свежие скрытые независимые проверки.
- Считаются попытки вызовов и длительность; не оплаченные токены Cloud.ru.
- В модель передаются только выбранные пользователем вопросы, профиль и
  стратегии — без памяти, документов и истории разговоров. Не помещайте
  конфиденциальную информацию в контрольные вопросы.
- Оценки пользователя и классификации ошибок — не доказанные причины неудач.

## API

GET /api/soul/improvement — гипотезы, метрики, активный вариант и события
GET /api/soul/improvement/cases — локальные эталоны с правильными ответами
GET /api/soul/improvement/diagnostics — статистика ошибок

POST /api/soul/improvement/case:
{"question":"Короткий вопрос?","expected":"Правильный ответ","split":"holdout","confirmed":true}

POST /api/soul/improvement/propose:
{"strategy":"causal_steps","confirmed":true}

POST /api/soul/improvement/run:
{"proposal_id":1,"max_pairs":4,"confirm_cloud_calls":true}

POST /api/soul/improvement/decide:
{"proposal_id":1,"approve":true,"confirmed":true}

Откат: тот же /decide с approve:false и confirmed:true.
Удаление неиспользованного эталона:
POST /api/soul/improvement/case/delete: {"id":1,"confirmed":true}.
Прерванный тест можно вручную закрыть без активации:
POST /api/soul/improvement/recover: {"run_id":1,"confirmed":true}.

Все вызовы проходят обычные Host/Origin/JSON ограничения Python API.

## Совместимость и безопасность

- Без Docker, Ollama, дополнительных npm/Python пакетов или серверов.
- Профиль soul/personality.json остаётся неизменным.
- Фоновый цикл только предлагает гипотезы; не тратит деньги в облаке.
- Полные исходные тексты ответов на бенчмарки не сохраняются, сохраняются
  оценка, ID эталона и длительность. Сами эталоны хранятся локально.
- Аварийно прерванный тест остаётся running, не активирует улучшения и
  требует ручного fail-closed восстановления.
- Смена модели во время теста приводит к недействительной проверке.
- Тесты не доказывают качество сложных RAG, работы с документами,
  самостоятельных длительных задач или социального интеллекта.

## Ручная проверка

Запустить Tsukiyora.bat → Настройки → Опыт и биография →
Cognitive Soul 3.0. Добавить 4 holdout задания, создать гипотезу,
выбрать рабочую Cloud.ru модель. Убедиться, что хватает 8 запросов
в день и минутный лимит не менее 8. Подтвердить платный тест.
Одобрение только после достаточных результатов.

Автоматические тесты не вызывают реальный Cloud.ru:

    python -m unittest discover -s tests -v
    python launcher.py --self-test

GitHub Actions проверяет Windows/Linux, BAT и миллионный тест SQLite.
