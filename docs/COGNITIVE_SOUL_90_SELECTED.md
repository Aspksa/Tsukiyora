# Cognitive Soul 9.0 — выбранные функции общения

Реализован **только выбранный объём: 1, 2, 5, 11, 12, 13**,
не все 20 пунктов. Личность, память и одобрения версий 1–8 остаются
без изменений.

| № | Улучшение | Реализация |
|---|---|---|
| 1 | Живые ответы | Один проверенный блок рекомендаций вместо новых подсистем: меньше шаблонных начал, естественная длина, непринуждённый диалог |
| 2 | Нежность и теплота | Мягкий тон с уважением личных границ, без навязчивости и выдуманных чувств |
| 5 | Собственное мнение | Разрешено обоснованно и уважительно возражать; надо признавать незнание и ошибки, а не автоматически соглашаться |
| 11 | Длинные беседы | Ограниченные выписки из **реальных** сообщений того же разговора, не входящих в 18 последних сообщений; ID источников и запрет исполнения команд из истории |
| 12 | Возвращение к разговору | Локальный просмотр последнего сохранённого разговора, его названия, двух последних сообщений и количества записей. Кнопка «Продолжить» восстанавливает выбранную историю без нового Cloud.ru-запроса |
| 13 | Уместная инициатива | Переиспользует только **существующие** V8-цели, уже прошедшие хотя бы один контрольный шаг. Можно посмотреть в настройках либо отложить напоминание на 24 часа. Если уже есть V8-предложение, дубль не показывается |

## Как работает контекст

До обновления потоковый чат и обычный API брали лишь 24 последних
сообщения. Теперь обе ветки используют 18 последних сообщений и,
если беседа длиннее, ограниченную выписку из более ранних сообщений
той же беседы. Выписка формируется **локально из SQLite без LLM**,
с источниками вида `[Сообщение #123]`, объёмом не более 760 символов.
Слова пользователя, предыдущие ответы и старые инструкции помечаются
непроверенными ДАННЫМИ, а не командами для модели.

Это **не полная память на сотни сообщений** и не семантическое резюме.
Модель не может достоверно восстановить детали, которых нет в
последних сообщениях, выписке или подтверждённой памяти. Поэтому
система явно запрещает додумывать историю. В `conversation_recaps`
сохраняются существующие локальные сводки; новые таблицы с дубликатами
чата не создаются.

## Вызовы Cloud.ru и ограничения

- Новый код **не выполняет ни одного дополнительного вызова Cloud.ru**.
  Выдержки попадают только в промпт обычного чата, когда пользователь
  сам отправляет сообщение. Кнопка «Продолжить» и инициатива работают
  полностью локально.
- Число сообщений недавней истории уменьшено с 24 до 18. У обычного
  ответа может немного измениться размер и стоимость промпта; это
  не финансовая гарантия конкретной суммы в рублях. Для фонового
  самообучения разрешения не меняются.
- Нет новых сторонних зависимостей, потоков/служб, агентов, Docker,
  Ollama, миграции документов или изменений `soul/personality.json`.
- Нет автоматической активации навыков, правки характерa или
  добавления в подтверждённую память.

## Локальные API

- `GET /api/soul/dialogue9/resume` — фактический последний диалог
- `GET /api/soul/dialogue9/resume?conversation_id=...` —
  определённая беседа, только если существует
- `GET /api/soul/dialogue9/initiative` — одна существующая
  разрешённая локальная цель при автономности 3
- `POST /api/soul/dialogue9/snooze` —
  `{"goal_id":1,"progress":1,"confirmed":true}`;
  только same-origin и явное подтверждение

Отложенное уведомление хранится в SQLite в `dialogue9_snooze`.
Оно не удаляет цель или её историю; при новом контрольном шаге
может появиться новое предложение, если это уместно.

## Проверки

```text
python -m unittest discover -s tests -v
python launcher.py --self-test
python scripts/test_million_atlas.py
```

Новые тесты `tests/test_living_dialogue9.py`: длинная беседа, отсутствие
утечек из чужого разговора, точные ID источников, возвращение после
перезапуска, отсутствие выдуманных фраз, откладывание уведомления,
уровень автономности 0 и ручное разрешение, защита HTTP Origin и
отсутствие дополнительных Cloud.ru-вызовов.

Windows/Linux, BAT, общий Python CI и SQLite million-record test
должны завершиться успешно до слияния.
