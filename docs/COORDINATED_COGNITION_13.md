# Tsukiyora 13.0 — Coordinated Cognition

Выбраны **29 из последних 30 улучшений**: **1–4 и 6–30**. Пункт **5 (адаптация нагрузки на CPU/RAM)** исключён и не вводится через другие настройки.

Это безопасное продолжение существующих Cognitive Soul, Memory 11, Living Dialogue 9 и Inner World 12. Не устанавливает Mem0, Letta, Graphiti, отдельную базу, фоновый сервис, Docker/Ollama или локальную LLM. Остаётся TypeScript/Canvas/CSS + Python API + SQLite, Node только для UI.

## Функциональные изменения, внесённые в этом PR

- **Фоновая очередь**: 45 прежних задач, один работник. Фиксированный приоритет обслуживания целостности и памяти; задача, просроченная более чем на час, получает максимальный приоритет. Без изменения интервалов заданий и без CPU/RAM-адаптации.
- **Фоновый блокнот V12**: персистентные курсоры по типам источников, выдача в порядке возрастающих ID и ротация категорий. Нет вечной обработки только двух самых новых записей. После очистки старых метаданных тот же источник не создаётся заново без нового ID, хотя весь прежний источник остаётся в SQLite. До 8 новых заметок за цикл. Прерывание внутри уже выполняющейся операции не гарантируется.
- **Временная память**: ручные аннотации `effective_from/effective_until` и `recorded_at` в **одной SQLite**. Каждый новый набор дат добавляется в журнал; старые аннотации сохраняются для проверки истории и не применяются после исправления/удаления исходного текста. Конечная дата исключается. Новая служба не объявляет даты автоматически проверенной истиной.
- **Векторный поиск по историческим данным**: локальный инкрементальный индекс десятибитных корзин (только существующие embeddings), работающий порциями в прежней задаче `vector_repair`. Учитывает как ранние, так и новые записи. Выбор кандидатов приблизительный, полнота ближайших соседей не гарантирована; неизменённый V11 ограниченный recent-пул сохранён как запасной механизм.
- **История решений**: исходные `memory_revisions` дополняются ручным названием сущности и причиной даты; отдельный `timeline` показывает исправления, объяснения и версии без переписывания данных.
- **Временной поиск**: по запросам с `as_of` (в V11) источник должен проходить проверку даты создания **и** последней действующей аннотации текущей версии. Это не полноценный снимок исторической базы и не доказывает, что утверждение было верным.
- **Единый реестр проверок**: существующие pending-факты, противоречия, цели, кандидаты Skill Forge и предложения по личности доступны в одном read-only списке ID источников. Решение остаётся за исходным модулем и владельцем.
- **Локальная диагностика возможных причин ошибок**: простые текстовые признаки в ранее сохранённых отрицательных отзывах. Никакой выдачи сырого текста во внешние метрики и никаких вымышленных выводов о когнитивном состоянии модели.
- **Контекст коротких реплик**: в объединённый V10-контекст иногда добавляется исходное предыдущее сообщение пользователя с ID для «да / нет / продолжай / не то». Такая подсказка *не* считается новым разрешением или подтверждением действия.
- **Эталонный тест извлечения**: пользователь сам одобряет вопрос и ожидаемый ID активного факта. Сервис считает Recall@k и p50/p95 по локальным запросам. Это проверка поисковой подсистемы, **не независимая оценка правильности текста LLM**.
- **Новый экран в настройках**: состояние фоновой очереди, активные проверки, время действия воспоминания, просмотр его истории, явное подтверждение эталона и запуск локальной оценки.

## Карта 29 выбранных пунктов: где реализованы и где ограничения

| Пункты | Направление | Реальный механизм / ограничение |
|---|---|---|
| 1 | Приоритет | Новый фиксированный priority_for + возраст ожидания |
| 2 | Устранение повторов | Единая read-only доска по ключу источника; владелец задачи остаётся прежним |
| 3 | Маленькие вычисления | Ограниченные порции Inner World 12; не все прежние тяжёлые работы умеют приостановку |
| 4 | Checkpoints | Новые устойчивые курсоры V12 + существующие idempotent SQLite jobs |
| 6 | Общая история | Существующий V5 event журнал + 13.0 обзор; отдельные исходные журналы пока сохранены |
| 7 | Два времени | Создание записи + ручная дата действия/recorded_at |
| 8 | Решения во времени | `memory_revisions` + новый `timeline` |
| 9 | Сущности | Разрешённые пользователем `entity_key`; автоматического разрешения омонимов нет |
| 10 | Причина | Ручное `rationale` с исходным ID и датой |
| 11 | Уровни памяти | Существующие MemoryStore, LayeredMemory, V9/V10 и V11 |
| 12 | Актуальность | SHA-проверка V11 + отсеивание устаревших временных аннотаций |
| 13 | Вся история | FTS5 по всему тексту и новый инкрементальный индекс корзин для **ранее сохранённых векторов**; полный охват достигается только после фоновой индексации, ANN recall не гарантирован |
| 14 | Забывание | Существующая защита history/revisions; активная память изменяется только по команде |
| 15 | Ошибки | Единая доска существующих отзывов, Academy, Forge и V7 |
| 16 | Возможные причины | Текстовые сигналы из отрицательных отзывов, без доказательства причинности |
| 17 | Контрольные задания | Ручные эталоны поисковой подсистемы и прежние V7 кейсы |
| 18 | Перенос навыков | Прежний Skill Forge; не переписан и не активирует навыки автоматически |
| 19 | Тестирование стратегий | Прежний V7/Forge shadow mode |
| 20 | Регрессии | Прежний Academy rollback/V7 verdict + тесты SQLite |
| 21 | Курсоры блокнота | Реализована ротация и продвижение ID всех девяти категорий |
| 22 | Польза фоновых задач | Показатели проверок и эталонов; **пока нет отдельной причинной метрики качества LLM** |
| 23 | Непрерывность диалога | V9/V10 + осторожная подсказка с исходным ID |
| 24 | Инициатива | Прежние V8/V9/V12; нужен дальнейший единый лимит уведомлений |
| 25 | Короткие реплики | Новый `followup_hint` с источником, без притворного «понимания» |
| 26 | Характер | Существующий V8 approved_style; личность не меняется |
| 27 | Контекст | Прежний общий V10 composer, новый краткий hint |
| 28 | Проверка выводов | V11 source flags + read-only review board; **не отдельный LLM-вызов** |
| 29 | SQLite | Прежние WAL, snapshots, backup verification + новые неизменяющие таблицы |
| 30 | Реальные тесты | Данные пользователя как holdout, тесты Windows/Linux/истории/источников/скорости |

**Не следует считать всю таблицу 29 новыми независимыми внедрениями.** Пункты, которые опираются на прежний код, остаются соответствующими его реальным ограничениям. Для завершения полнофункционального плана ещё нужны: гарантированный высокоточный ANN-поиск по всем векторам, перенос проверяемых правил на новые навыки без модели, полные причинные проверки улучшения диалога, прерываемость всех долгих задач. Они требуют отдельной оптимизации и тестов и здесь не объявляются готовыми.

## API

- `GET /api/soul/coordinator13` — агрегаты, политика очереди, ручные эталоны.
- `GET /api/soul/coordinator13/reviews` — ссылки на исходные записи, не их приватное содержимое.
- `GET /api/soul/coordinator13/issues` — только счётчики лексических сигналов.
- `GET /api/soul/temporal13/timeline?memory_id=N` — история и аннотации факта.
- `POST /api/soul/temporal13/annotate` — даты, причина, ID, `confirmed:true` и same-origin.
- `POST /api/soul/coordinator13/eval-case` — ручной эталон, `confirmed:true`.
- `POST /api/soul/coordinator13/benchmark` — ручной локальный тест, `confirmed:true`, откладывается при активном чате.

```sh
python -m compileall -q launcher.py tsukiyora tests
python -m unittest discover -s tests -v
python launcher.py --self-test
```

## Неприкосновенные условия

- `soul/personality.json` не изменён.
- Новые факты, навыки, настройки характера и внешние действия **не** применяются автоматически.
- В фоне не запускаются новые платные Cloud.ru-запросы.
- Имеющийся отдельный механизм Skill Forge с явными разрешениями/бюджетом остаётся под прежним контролем.
- Нет новой CPU/RAM-адаптации (пункт 5 исключён).
