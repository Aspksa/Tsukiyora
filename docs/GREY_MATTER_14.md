# Tsukiyora 14.0 — GREY MATTER

В этой версии переиспользованы архитектурные идеи [DSPy/GEPA](https://github.com/stanfordnlp/dspy), [Hindsight](https://github.com/vectorize-io/hindsight), [Mem0](https://github.com/mem0ai/mem0), [Graphiti](https://github.com/getzep/graphiti) и [LangGraph](https://github.com/langchain-ai/langgraph). **Ни один из этих фреймворков не установлен, не скопирован целиком и не становится скрытой зависимостью.** Цель — локальная проверяемая логика, контроль прогресса и аккуратная координация существующего кода.

Это **не настоящий биологический мозг, не субъективное сознание и не самообучение весов облачной модели**.

## Новое в PR

- `tsukiyora/cognition/grey_matter14.py` — небольшой детерминированный движок **пропозициональных правил** `если … то …`, работающий по **явно заданным** пользователем символическим предпосылкам.
- Результат имеет ровно четыре состояния: `entailed` (выводится), `refuted` (выводится отрицание), `unknown` (нет доказательства), `conflict` (выводится и утверждение, и отрицание).
- Запись результата содержит конкретное правило или исходную предпосылку, а не выдуманный свободный «монолог размышлений» LLM. Реальная истинность фактов **не** устанавливается.
- При сохранении эталонного задания требуется явное `confirmed:true`, пользовательский ожидаемый вывод и, по желанию, ссылка на **активное** `memory_items.id`. Если такой источник позже исправлен или удалён, задание не может подтверждать положительный результат до ручной перепроверки.
- Проверка эталонов показывает `tested`, `passed`, ошибочные выводы и время локального выполнения. Это **качество символического движка на подтверждённых тестах**, не независимая оценка общего интеллекта ИИ.
- Защищённая фоновая работа: не добавлена новая очередь, новый worker, новая служба или Cloud.ru-вызов. В существующей задаче `cog12_reflect` выполняется максимум **6** символических примеров, хранится SQLite-курсор и одна числовая дневниковая запись за сутки. Фоновая проверка подчиняется прежнему уровню V8 и разрешению `local_practice`.
- Переиспользованы `ReasoningAudit` (источники), `ReflectiveOptimization` (ручные A/B), `CognitiveEvolution` (кандидаты/эталоны), `CognitiveSupervisor7` (безопасность навыков), `CognitiveCoordinator13`, `Memory11/13`, `InnerWorld12`, `SOUL ACADEMY` и `Skill Forge`. Никаких новых автоматических прав на изменение этих систем нет.
- Показатели уже существующих экспериментов отражаются в состоянии GREY MATTER, но **логические тесты не служат основанием автоматического одобрения стратегии**.
- В настройках добавлен раздел с редактором символических фактов/правил, просмотром результата, явным сохранением эталона и проверкой сохранённых заданий.

## Пример логики

Для входа:

```json
{
  "facts": ["a"],
  "rules": [
    {"when":["a"],"then":"b"},
    {"when":["b"],"then":"c"}
  ],
  "target": "c",
  "expected": "entailed"
}
```

Движок выведет `c` через правила №1 и №2. Для `!c` одновременно с `c` вернёт `conflict`. Если ни `c`, ни `!c` не выводятся, вернёт `unknown`. Отрицание здесь — символическая метка, а не автоматическое извлечение реальных фактов из русского текста.

Система ограничена: до **32 исходных предпосылок, 32 правил, четырёх условий на правило и 32 итераций вывода**. Не выполняет произвольный код.

## Что заимствовано концептуально из исследованных проектов

| Источник | Переиспользованная идея | Чего здесь нет |
|---|---|---|
| DSPy / GEPA | Базовые метрики, измеряемые варианты и контролируемые изменения стратегий | Автоматическая оптимизация произвольных промптов или весов модели |
| Hindsight | Разделение наблюдения, воспоминания и ретроспективной проверки | Генеративный автономный `reflect` и его LLM-вызовы |
| Mem0 | Актуальность источника и контролируемая память | Полное копирование SDK и заявленные метрики Mem0 |
| Graphiti | Связь с ID текущего факта и жизненным циклом версий | Отдельная графовая СУБД или автопревращение диалога в истинные факты |
| LangGraph | Персистентный курсор и восстановление разрешённых шагов | Дополнительные автономные агенты, LangGraph runtime и внешние сервисы |

## Прежний план 20 функций «серого вещества»

- **1–8: логика** — V10 выбирает стиль для диалога; GREY MATTER 14 теперь умеет проверять **явные символические правила**, отрицания, контрпримеры и недостаточность доказательств. Анализ естественной речи и истинной причинности по-прежнему зависит от облачной модели и надёжности источников.
- **9–16: развитие** — переиспользованы уже действующие V7/V8, ReflectiveOptimization, CognitiveEvolution, Academy, Forge и Inner World 12. Новая логическая тестовая база **не** переписывает и не активирует эти навыки.
- **17–20: проверка прогресса** — фоновая локальная проверка ограниченной партии задач, сохранённые результаты, контроль версий источника и объединённая сводка существующих испытаний.

**Не все 20 пунктов являются 20 новыми полнофункциональными реализациями.** Переиспользование не означает, что Tsukiyora доказала способность самостоятельно улучшать мышление LLM. Признаки роста необходимо проверять на новых репрезентативных задачах, в том числе со слепыми эталонами, а не только на уже сохранённых собственных примерах.

## API

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/soul/grey14` | Состояние ядра и старых A/B/эволюционных испытаний |
| GET | `/api/soul/grey14/cases` | Метаданные локальных эталонов и текущая актуальность источников |
| POST | `/api/soul/grey14/preview` | Только локальная символическая проверка, без сохранения |
| POST | `/api/soul/grey14/case` | Сохранить эталон, обязательно `confirmed:true` |
| POST | `/api/soul/grey14/benchmark` | Запустить локальный тест, обязательно `confirmed:true`; откладывается при активном чате |

Изменяющие запросы проходят прежнюю проверку same-origin; приватные тексты диалогов не добавляются в рабочий блокнот.

## Ограничения и безопасность

- База только SQLite, версия схемы **15**. Миграция старой БД проходит через существующий `MigrationGuard`, который делает резервный снимок до изменения схемы.
- Персона `soul/personality.json` не переписывается. Включение навыков и новых поведенческих стратегий остаётся ручным, после действующих контролей V7/V8.
- Node.js используется только для сборки UI, Python — единственный API, существующий BAT не заменён.
- Нет новых зависимостей, Docker, Ollama, дополнительных сервисов или фоновых расходов Cloud.ru.
- «Мысли» = инспектируемые результаты формальных вычислений, а не приватная цепочка рассуждений облачной модели.

Проверки:

```bash
python -m unittest discover -s tests -v
python launcher.py --self-test
```

GitHub CI дополнительно проверяет Windows и Ubuntu на одном финальном SHA перед слиянием.
