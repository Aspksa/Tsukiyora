# Tsukiyora · живой чат, память и развитие (v0.4)

## Что реализовано в этой версии

**1. Диагностика Cloud.ru.** В Настройках → Cloud.ru нажмите «Проверить живой ответ». Цукиёра отправит реальный короткий запрос к уже выбранной модели Foundation Models и покажет ответ либо ошибку доступа/квоты/сети. Проверка может расходовать токены. **В GitHub Actions реальный запрос без вашего ключа невозможен:** тесты используют имитацию облачного API.

**2. Потоковый чат.** Браузер читает SSE-события `start`, `token`, `done`, `stopped`, `error` от локального Python API. Символы появляются по ходу ответа. «■» останавливает поток: Python устанавливает событие и пытается закрыть upstream-соединение. Уже выведенный неполный ответ **не сохраняется как завершённый**. Если сеть прервалась, можно повторить запрос с прежним client ID. Команда отправки не доступна, когда нет подключённой модели. История уже завершённых ответов сохраняется в SQLite.

**3. Подтверждаемое запоминание.** После завершённого ответа система анализирует **только явно выраженные** утверждения пользователя, например «я люблю…», «меня зовут…», «я работаю…», «запомни…». Такая эвристика не покрывает все возможные факты и может предлагать лишнее. Она **не утверждает истинность**. В Настройках → Воспоминания → Предложения памяти откройте карточку и нажмите «Запомнить» или «Отклонить». До подтверждения запись не становится постоянной памятью. Каждое принятое воспоминание содержит тип, текст, источник сообщения (`source_ref`) и статус «сообщено пользователем». Никакой автоматической правки защищённых ценностей личности.

**4. RAG и связи.** Локальный поиск на Python (слова + нечёткое совпадение) без внешних библиотек работает офлайн. Кнопка «Поиск по смыслу» использует дополнительно **Cloud.ru LLM reranking** для сортировки найденных кандидатов, если модель доступна. Это отдельный потенциально платный запрос; **векторных embeddings на этом этапе нет**. Официальная OpenAPI-спецификация Foundation Models ограничена `GET /v1/models` и `POST /v1/chat/completions`: мы не выдумывали неизвестный endpoint эмбеддингов. Кандидаты ограничены локальной предварительной выборкой: синонимы без общих слов могут быть пропущены.

У памяти есть таблица связей `memory_links`, источники и типы `related` / `possible_conflict`. Противоречия — лишь **сигналы по эвристикам**, не проверенные выводы. При изменении воспоминания связи пересчитываются. Записи и их источники можно увидеть в интерфейсе.

**5. Эволюция личности.** Характер из `soul/personality.json` остаётся защищённым. Отдельный `soul_journal` фиксирует завершённые диалоги и подтверждённые записи. Цукиёра может менять **манеру общения** на основании явно сохранённых предпочтений пользователя («говори короче», «общайся нежнее»), но не изменяет ядро личности или исполняемые файлы самостоятельно. Биография хранится в типе памяти `biography` и связывается с сообщениями. Это **симуляция последовательного характера и опыта**, не доказательство сознания или настоящих чувств.

## Простая проверка

1. Обновить проект из GitHub, запустить `Tsukiyora.bat` на Windows.
2. В Настройках → Cloud.ru ввести реальный API-ключ (хранится в оперативной памяти локального Python-процесса), получить модели, выбрать модель.
3. Нажать «Проверить живой ответ». Посмотреть статус. Ключ не вставлять в GitHub.
4. В чате отправить простое сообщение; увидеть текст по частям, попробовать «■». Проверить, что завершённый разговор есть в истории.
5. Написать «Я люблю зелёный чай». После ответа в Настройках → Воспоминания → Предложения памяти подтвердить запись, а затем проверить поиск и источник.

## Локальные маршруты API

- `POST /api/cloud/diagnose`: реальная проверка Cloud.ru, платная согласно условиям провайдера.
- `POST /api/chat/stream`: тело `{content,conversation_id?,client_message_id?}`; SSE события по мере генерации.
- `POST /api/chat/stop`: `{stream_id}`, отмена активного локального потока.
- `GET /api/soul/suggestions`: ожидающие подтверждения записи.
- `POST /api/soul/review`: `{id,approve: boolean}`; только человек подтверждает или отклоняет.
- `POST /api/soul/search`: `{query,semantic: boolean}`; режим semantic вызывает LLM, обычный режим офлайн.
- `GET /api/soul/links`: граф связей с пометками возможных конфликтов.
- `GET /api/soul/journal`: локальный журнал развития.

Всё хранится **только в локальной** SQLite внутри `data/`. Папка в `.gitignore`. При обращении к Cloud.ru провайдеру передаются сообщения и релевантные записи памяти — не отправляйте конфиденциальные материалы, если такой обмен вам запрещён. В зависимости от модели данные могут обрабатываться во внешней инфраструктуре Cloud.ru. У базы пока нет шифрования, только контроль доступа ОС. Резервную копию создавайте через существующую кнопку.

## Ограничения

- Нет автономной «души», самосознания, фоновой обработки всех документов, внешних агентов или переписывания своего кода.
- Нет настоящей векторной БД и облачного API embeddings; работает гибридный локальный поиск и LLM-rerank.
- Смысловое переранжирование и проверка модели могут расходовать дополнительные токены. Без API-ключа доступны локальный поиск, ручные воспоминания и биографический журнал, но нет ответов чата.
- Закрытие браузера не всегда гарантирует немедленную отмену уже отправленного платного запроса; используйте кнопку «■». При сетевых задержках Cloud.ru прекращение передачи может быть не мгновенным.
- Секрет ключа не сохраняется и вводится заново при новом запуске сервера.
- Для новых сообщений используется до 24 последних реплик; история в SQLite хранится полностью.

## Проверки

GitHub Actions: Windows и Linux, Python 3.13 и браузерный JavaScript. Тесты имитируют Cloud.ru и проверяют поток SSE, остановку, JSON, SQLite, повтор запросов, источники, поведение памяти и поиск. Живое взаимодействие с реальным Cloud.ru и внешний вид на вашем Windows-ПК нужно проверить с вашим ключом отдельно.

Документация API Cloud.ru: https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs
