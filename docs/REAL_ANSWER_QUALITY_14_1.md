# Tsukiyora 14.1 — GREY MATTER: Real Answer Quality

Этот этап выполняет следующий запрос владельца: **проверять, помогает ли GREY MATTER улучшать настоящие ответы Цукиёры**, а не только её формальные символические задачи. Сохраняет прежние защиту личности, одно Python API, SQLite, TypeScript/Canvas/CSS UI, BAT, Node только для фронтенда и без новых зависимостей, Docker, Ollama или дополнительных Cloud.ru-вызовов.

## Конкретная реализация

1. **Завершённые ответы**: оба пути (`/api/chat` и `/api/chat/stream`) после сохранения реального ответа вызывают общий `RealAnswerQuality.observe`. Старая `ReasoningAudit` повторно используется для проверки настоящих ссылок вида `[Память #ID]`. В обычном чате также сохраняется существующая оценка числа токенов по длине текста через `usage_estimates`, аналогично потоку.
2. **Локальная проверка источников**: фиксируются количество ссылок на существующие, отсутствующие и потенциально конфликтующие записи, а также простой сигнал о запросе ссылок. Сигнал отсутствия ссылки не доказывает ошибку: ассистент может честно ответить, что источника нет. В таблице `answer15_audits` находятся только ID сообщения, SHA ответа, состояния и числовые счётчики; нет копий содержимого переписки.
3. **Подтверждённая человеческая оценка**: ты выбираешь **реальный ID сохранённого ответа** в текущей беседе и оцениваешь по отдельности фактическую точность, ясность, обоснованность источниками и сохранение контекста. Каждое поле: «да», «нет» или «не оцениваю». Без `confirmed:true` запись невозможна; нельзя оценить чужую роль или несуществующее сообщение. Оценки — **суждения пользователя**, а не независимо доказанная истина.
4. **Влияние на последующий разговор**: только **после твоей отрицательной оценки** следующая реплика **этого же диалога** получает короткую, фиксированную контекстную подсказку: не выдумывать факты/источники, яснее объяснять или учитывать прежний вопрос. Это часть **одного уже разрешённого ответа Cloud.ru**, без второго запроса. Подсказка не меняет `soul/personality.json`, утверждённые факты, модель, навыки, стратегии и разрешения.
5. **Метрики настоящего общения**: отчёт группирует оценки по реально сохранённому идентификатору модели (`usage_estimates`) и считает число наблюдений и доли «да» для каждого критерия. Показатели с разными моделями, вопросами и выборками **нельзя автоматически считать доказательством причинного прогресса**. Независимый слепой набор одинаковых задач и контролируемое сравнение по-прежнему необходимы.
6. **Удобство**: в настройках новый раздел GREY MATTER 14.1. В карточке каждого настоящего ответа можно открыть подробную оценку, проверить ссылки и сохранить отзыв. История переписки не дублируется в таблицах качества.

## Структура и хранение

- `tsukiyora/cognition/real_answer_quality.py` — единственный новый Python-модуль.
- `answer15_audits` — метаданные проверенных источников только у завершённых ответов.
- `answer15_reviews` — пользовательские бинарные оценки по четырём измерениям, с `NULL` для неоценённых пунктов.
- Версия SQLite-схемы **16**, перед обновлением существующей базы прежний `MigrationGuard` выполняет резервный снимок.
- Никакого отдельного фонового worker: проверка запускается локально после завершения ответа или вручную, а не каждые N секунд.

## API

| Метод | Путь | Права |
|---|---|---|
| GET | `/api/soul/answers15` | Счётчики и оценки по моделям без копий сообщений |
| GET | `/api/soul/answers15/recent?conversation_id=...` | Метаданные сохранённых ответов текущего диалога |
| POST | `/api/soul/answers15/review` | Четыре оценки, `confirmed:true` и прежний same-origin |
| POST | `/api/soul/answers15/inspect` | Повторная локальная проверка ссылок, `confirmed:true`, без платного вызова |

Два независимых измерения сохраняются отдельно: формальный символьный GREY MATTER 14.0 и человеческая оценка реальных ответов 14.1. Они не подменяют друг друга.

## Проверки

```sh
python -m unittest discover -s tests -v
python launcher.py --self-test
```

GitHub Actions проверяет Windows/BAT, Linux, SQLite, Python и масштабный Atlas. Добавлены тесты реальных сообщений, недействительных цитат, отсутствия Cloud-запросов при анализе, согласия пользователя, приватности, сохранности личности, миграции и одинаковой оценки ответов после перезапуска.

**Предел доказательств:** этот этап даёт работающий способ собирать и использовать обратную связь о настоящем общении. Он не даёт оснований утверждать, что облачная модель сама обучилась или стала умнее. Для такого вывода понадобятся достаточные репрезентативные контрольные диалоги с зафиксированной моделью и независимой оценкой результатов.
