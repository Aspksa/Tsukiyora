# TSUKIYORA — минималистичный интерфейс v1

## Главный принцип
На экране только то, чем пользователь реально пользуется. Никакой панели с техническими параметрами, пустых вкладок и десятков кнопок. Чёрный фон, тонкие золотые акценты, аккуратная векторная анимация. Технологии остаются: TypeScript + HTML5 Canvas + CSS, локальный Python API, SQLite, Node.js только для фронтенда.

## Единый экран
- Верхняя узкая строка: имя «Цукиёра», ненавязчивый индикатор «локально / модель подключена», одна кнопка настроек.
- Левая / центральная зона: анимированное ядро кицунэ на Canvas. Без большого статического заголовка, декоративных меню и бесполезных значков.
- Правая зона: цельный чат без визуальной рамки; история сообщений, поле ввода, отправка / остановка ответа.
- На узком экране интерфейс адаптивен: ядро уменьшено, чат занимает основное место.
- Динамические состояния показывать только при реальном событии (ответ, сохранение памяти, ошибка), не имитировать активность.

## Настройки: только 4 раздела
1. **Нейросеть:** Cloud.ru или другой одобренный облачный провайдер, ключ, выбор модели, проверка подключения.
2. **Голос:** включить/выключить и выбрать голос (только если голосовой движок действительно подключён).
3. **Память:** показать статус SQLite, объём, включить/выключить запоминание.
4. **Данные:** экспорт резервной копии и восстановление с явным подтверждением.

Не делать отдельные страницы для параметров порта, логов, индексов, технических циклов и внутренних алгоритмов. Диагностика доступна при ошибке или в свёрнутом разделе «Дополнительно», не отвлекает по умолчанию.

## Проверки удобства
- На первом запуске показывать только действие, необходимое для подключения облачной модели; пока модели нет — честно объяснять, что онлайн-ответы не работают.
- Не показывать неработающие кнопки; незавершённые функции не маскировать под готовые.
- Без новых библиотек, Docker, Ollama, других баз данных, дополнительных фоновых служб без согласования.
- Память и личные ключи не отправлять в публичный репозиторий.
- Производительность: ограничение частоты кадров Canvas при отсутствии активности, поддержка prefers-reduced-motion, отсутствие постоянных дорогих эффектов.

## Приоритет реализации
1. BAT + Python API + загрузка soul/personality.json.
2. Один лаконичный экран с ядром и статусом.
3. Рабочий чат с подключаемой облачной моделью.
4. Только затем настройки по мере фактической готовности функций.

Этот файл задаёт UX-направление, не подтверждает реализацию незавершённых функций.
