# Цукиёра v0.6 — память, опыт и локальное развитие

## Быстрая проверка на Windows

1. Открой `main` в GitHub → **Code → Download ZIP**, распакуй проект в папку на ПК или внешнем SSD.
2. Запусти `Tsukiyora.bat`. Python 3.10+ обязателен, Docker/Ollama не нужны. Браузер должен открыться на `127.0.0.1`.
3. Нажми настройки → **Cloud.ru**. Введи ключ Foundation Models, загрузи список, выбери чат-модель. При необходимости отдельно выбери embedding-модель в разделе памяти.
4. Кнопка **«Проверить Cloud.ru»** делает **реальные** запросы: каталог моделей, обычный ответ и SSE-поток, а если выбран embedding-провайдер — короткий запрос эмбеддинга. Запуск только вручную; **каждая проверка может стоить токены**. Показывает результат по каждому этапу или ошибку, но не сохраняет ключ и не объявляет успех без ответа сервиса.
5. Отправь сообщение в чат, проверь потоковую выдачу, остановку, историю сообщений и предложения памяти. Подтверди факт в Настройках → Воспоминания.
6. Проверь **«Качество памяти»**: повторы, возможные противоречия и сходство по уже имеющимся векторам. Ни одна запись автоматически не удаляется.
7. Покрути колесо мыши над картой памяти для масштаба, перетащи карту, кликни по соте, чтобы открыть запись. Двойной клик сбрасывает масштаб.

Невозможно проверить реальный Cloud.ru без **твоего собственного** ключа, доступа к провайдеру и установленной модели. Не отправляй ключ в сообщения, GitHub или тестовые логи. CI использует только тестовые заглушки.

## 1. Умная память без потери данных

- **Текстовый + векторный** поиск из v0.5, векторы и SHA256 кэшируются в единой локальной SQLite. Индексация в Cloud.ru — только по нажатию кнопки и отдельному подтверждению.
- Новый `memory_quality.py`: эвристика выявляет почти одинаковые записи, вероятные противоречия по отрицаниям и смысловые дубли, когда оба вектора уже локально сохранены. Ссылки на источники отображаются; **ни одна пометка не означает установленный факт**.
- `VectorMemory.repair()`: удаляет устаревшие привязки после изменений и восстанавливает связи, только если нужный вектор уже существует в кэше. **0 облачных запросов**.
- Подтверждение новых воспоминаний обязательно, полная история диалогов и корректировок сохраняется. Для резервных копий используется SQLite Backup API.

## 2. Обучение на опыте

Новый `experience_engine.py` группирует **явно оставленные пользователем** оценки ответов по точности, краткости, понятности и ссылкам на источники. После нескольких негативных оценок формируется фиксированная безопасная рекомендация. Непроверенные инструкции из текста отзыва **не вставляются** в системный запрос. При смене оценок стратегия пересчитывается.

Учебные цели `observe`, `practice`, `improving` формируются только по реальным оценкам, а не по фантазиям об опыте. Это ограниченное обучение манере ответов, не обучение весов нейросети и не редактирование своего кода.

## 3. Биография и модель характера

Ядро личности `soul/personality.json` не меняется фоновыми процессами. История событий строится по завершённым диалогам и **подтверждённым** воспоминаниям. Программный показатель тона (`warmth`, `focus`, `curiosity`) служит для интерфейса и адаптации ответов. Это **не доказательство настоящих чувств, сознания или понимания эмоций пользователя**.

## 4. Фоновые циклы без дополнительных сервисов

Пока запущен Python API, локальный поток раз в 15 минут:
- проверяет SQLite;
- исправляет только локальные кэш-связи векторной памяти;
- пересчитывает ограниченное количество связей знаний;
- ищет подозрительные дубли и противоречия;
- обновляет учебные цели и записывает агрегированные показатели в SQLite.

Он **не отправляет данные в облако**, не запрашивает новую модель, не меняет программные файлы и завершается вместе с сервером. Диагностика не сохраняет содержимое личных сообщений в агрегированный дневник.

## 5. Карта памяти

Canvas рисует восемь секторов, реальные соты-воспоминания (до 180), рёбра-связи (до 400). При поступлении новых сведений кратко подсвечиваются только появившиеся записи. Масштаб, перетаскивание и переход к воспоминанию доступны без новой страницы. Отключение анимаций ОС (`prefers-reduced-motion`) соблюдается. Ненужных дополнительных вкладок и библиотек нет.

## Ограничения

- **Live-тест на личном ПК не выполнен на стороне GitHub:** реальный ключ не хранится в репозитории. Ошибки Cloud.ru, доступность конкретных моделей и открытие BAT на твоём компьютере требуют локальной проверки.
- Семантические дубли и противоречия — только **предложения к проверке**, возможны ложные совпадения и пропуски.
- Эмбеддинги требуют доступного у твоего аккаунта Cloud.ru embedding API. Без этого продолжает работать текстовый RAG и LLM-reranking, когда чат-модель доступна.
- Обучение касается правил общения и фактических ошибок по обратной связи, **не** переобучает облачную LLM и не делает ИИ автономным сознанием.
- База SQLite и локальные резервные копии не зашифрованы: защищай компьютер/SSD.
- Пользовательское состояние остаётся только в `data/`, за исключением контекста, явно отправляемого в Cloud.ru при общении или подтверждённой индексации.

## Разработка и тесты

```powershell
python -m unittest discover -s tests -v
```

GitHub Actions запускает тесты Python, синтаксис браузерного JavaScript и BAT smoke test на Windows и Linux (BAT-тест Windows-only). Для Cloud.ru использованы имитации ответов, а не настоящий ключ. Вносим изменения через рабочую ветку и PR, сливаем в `main` только после зелёных проверок.

- API: `GET /api/soul/quality`, `GET /api/soul/experience`, `POST /api/cloud/checkup`.
- Пример для checkup: `{"include_stream":true,"include_embeddings":true}`, `Content-Type: application/json`, только с локального origin.
- Существующие `POST /api/soul/feedback`, `POST /api/soul/vectors/index`, `GET /api/soul/graph` остаются совместимыми.
