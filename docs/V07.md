# Tsukiyora v0.7 — надёжная память и SOUL ACADEMY

Версия сохраняет первоначальный стек: **Python — единственный API-сервер, SQLite — единственная БД, HTML5 Canvas + CSS + JS-совместимый TypeScript — фронтенд**. Нет Docker, Ollama, локальных LLM, дополнительных сервисов или новых сторонних зависимостей.

## 1. Диагностика: реальное и локальное

В существующих настройках откройте **«Диагностика и сохранность»** → «Проверить систему». Это локальная проверка Python, целостности SQLite, файлов запуска, интерфейса и наличия локальных резервных копий. Отдельно показываются очередь обслуживания и **приблизительное** число токенов, оценённое по длине сообщений (не статистика счёта Cloud.ru).

В настройках **Cloud.ru** нажмите «Проверить Cloud.ru». Это отдельный **платный, пользовательский** запрос к настоящему API: каталог моделей, короткий ответ, SSE-поток, embeddings (если embedding-модель выбрана). В результате каждого шага видно `passed`, `failed` или `skipped`. Нет ключа — нет утверждения об успешной live-проверке. На чужом компьютере и в GitHub Actions эта проверка не выполняется.

Браузерные кнопки и внешний вид на вашем Windows-ПК следует проверить вручную. CI покрывает HTTP API, исходный HTML, JS-синтаксис и тестовый BAT-запуск на Windows; это не полная замена браузерного E2E-теста.

## 2. Многоуровневая память

Модуль `layered_memory.py` автоматически строит и восстанавливает в SQLite отдельный **производный индекс**:

- **Краткосрочная** — недавние реплики выбранного разговора, без автоматического переноса в память.
- **Эпизодическая** — подтверждённые события.
- **Семантическая** — подтверждённые факты, отдельные от векторных embeddings.
- **Автобиографическая** — подтверждённая биография и предпочтения.

У каждого долгосрочного факта сохраняются ссылки на исходное сообщение, приоритет и идентификатор последней ревизии. Исправления автоматически отражаются при следующем обслуживании; исходная история не удаляется. `traceability` отражает полноту происхождения, **не истинность** сведения.

Маршрут `GET /api/soul/layers?layer=episodic&limit=50`.

## 3. Самопроверка

Модуль `reasoning.py` проверяет существование ссылок вида `[Память #123]`, их активность и пометки возможного конфликта. Результаты хранятся в `reasoning_audits` и доступны в настройках «Опыт и биография». Если ссылка не существует, ответ отмечается как требующий проверки. Эта проверка **не доказывает истинность всех утверждений LLM** и не переписывает её ответ или память автоматически.

## 4. SOUL ACADEMY и характер

Варианты учебных целей — точность, ясность, краткость и источники. Только явные пользовательские оценки и комментарии могут менять ограниченные рекомендации по стилю будущих ответов. Защищённые свойства в `soul/personality.json` остаются неизменными. Успехи и ошибки сохраняются в журнале. Отображаемые «теплота», «внимание» и «интерес» — **модель состояния интерфейса, не настоящие эмоции**.

## 5. Локальное фоновое обслуживание, нагрузка и сохранность

`maintenance.py` ведёт SQLite-очередь из шести ограниченных работ: проверка целостности, восстановление уровней памяти, кэш-связей эмбеддингов, просмотр повторов и конфликтов, обновление уроков и резервное копирование. Не более одного задания за проход; **во время активного чата работа откладывается**. Фоновые задания **не вызывают Cloud.ru**.

`reliability.py` создаёт согласованные снимки с помощью SQLite Backup API, проверяет целостность, обновляет расписание. В штатном режиме снимок создаётся при первом доступном фоновом цикле и затем не чаще одного раза в 5 часов. Хранятся до 12 последних копий в `data/backups/`. Ручное копирование доступно в настройках. Автоматическое восстановление в работающую БД намеренно запрещено: это могло бы повредить данные.

### Восстановление после сбоя (только офлайн)

1. **Полностью остановите** `Tsukiyora.bat` и закройте окно запуска.
2. Откройте PowerShell в папке проекта; выполните `python restore_memory.py --list`, чтобы увидеть доступные снимки.
3. Выберите точное имя файла и выполните `python restore_memory.py --restore memory-YYYYMMDD-HHMMSS-xxxxxxxx.sqlite3 --confirm` (подставьте реальное имя из списка).
4. Утилита проверит блокировку запуска и целостность выбранного снимка, сохранит страховочную копию прежней БД и только после этого заменит файл. Если WAL-файлы ещё открыты, операция откажет без принудительного удаления.

**Не запускайте восстановление на работающем сервере.** Резервные копии содержат разговоры и память в **незашифрованном** виде; храните SSD в безопасности. Файлы `data/` исключены из GitHub.

## 6. Живая карта мозга

Python `GET /api/soul/graph` возвращает до **2400 реальных** записей за запрос, упорядоченных по типу (8 секторов), с данными о числе записей и видимых связях. Canvas использует малые шестиугольники, отсечение за границами окна, ограничение числа отрисованных связей и уменьшает частоту кадров при большой нагрузке. При сильном отдалении соты сворачиваются в **8 агрегированных кластеров** с реальными счётчиками. Работает масштабирование колесом, перетаскивание, просмотр по нажатию и управление с клавиатуры. Анимация всплеска запускается только при появлении новых записей; настройка уменьшения движения соблюдается.

Это не бесконечное отображение всей базы: если записей больше 2400, API сообщает об усечении. Для намного больших баз потребуется полноценная постраничная загрузка и проверка производительности в реальном браузере.

## Контрольные проверки

```powershell
python -m unittest discover -s tests -v
```

GitHub Actions выполняет Python компиляцию, JS-проверку и тесты на Windows и Linux. Ни один CI-тест не получает реальный секрет Cloud.ru. **Первый реальный вызов Cloud.ru, плавность интерфейса, поведение всех кнопок и запуск на вашем компьютере** требуют отдельной проверки пользователем.

Ни личные ключи, ни настоящие разговоры, ни SQLite-файлы не следует публиковать в публичном репозитории.
