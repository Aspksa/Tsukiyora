# Tsukiyora v0.8 — точность памяти и масштабируемый мозг

**Стек неизменен:** Python — единственный API-сервер, SQLite — единственная локальная БД, TypeScript (JS-совместимый, запускаемый браузером напрямую) + HTML5 Canvas + CSS. Нет Docker, Ollama, локальных LLM, дополнительных сервисов и новых сторонних зависимостей.

## 1. Диагностика: только фактически проверенное

В настройках → «Диагностика и сохранность» → «Проверить систему» доступны локальный `GET /api/system/selftest`, проверка SQLite, существования файлов интерфейса и запуска, проверки последних до трёх резервных копий с помощью `PRAGMA quick_check`, наличие ключевых элементов DOM и Canvas.

**Важно:** проверка DOM не выполняет нажатие всех кнопок. GitHub CI проверяет Python/JS-синтаксис, API, тестовый BAT на GitHub-hosted Windows, работу на Linux и данные в тестовой SQLite. Она не заменяет тест в пользовательском браузере. Отдельная кнопка «Проверить Cloud.ru» делает реальный запрос к модели/потоку/эмбеддингам **только с ключом пользователя и по его действию**; может расходовать токены. Без ключа такой тест не считается пройденным.

## 2. Точная память: SQLite FTS5 + связи + происхождение

`precision_memory.py` добавляет полнотекстовый индекс SQLite FTS5, если он доступен в сборке Python; если нет — работает ограниченный лексический поиск. Триггеры обновляют индекс при исправлении, удалении и добавлении фактов; фоновая задача восстанавливает недостающие записи после обновления старой базы. Ранжирование объединяет совпадения слов, мягкую текстовую близость и небольшой приоритет воспоминания. Поиск раскрывает релевантные непосредственные связи (`memory_links`) с пометкой `related` и сигналами `possible_conflict`.

`POST /api/soul/precision`:

```json
{"query":"ремонт фар лексус","limit":12,"include_links":true}
```

Каждый результат имеет ID, тип, источник и объяснимую оценку релевантности. `source_verified: false` означает, что источник доступен, но не является доказательством факта. **Неподтверждённые автопредложения не индексируются в долговременную память.** Поиск FTS5 полностью локальный, без платных обращений. Для векторного поиска по смыслу остаётся существующий отдельный режим Cloud.ru, требующий пользовательского разрешения; ни индексатор, ни фоновый когнитивный цикл сами не отправляют данные в Cloud.ru.

## 3. SOUL ACADEMY 2.0

`soul_academy.py` хранит учебные циклы в SQLite (`academy_goals`, `academy_cycles`). Анализируются **явные** оценки и комментарии пользователя по категориям точности, краткости, ясности и источников. Рассчитывается число наблюдений, доля положительных оценок и простая тенденция. На основе повторяющихся ошибок выбираются только заранее утверждённые безопасные стратегии. Эти стратегии используются в следующих диалогах — **без переобучения облачной модели или самостоятельного изменения Python-кода**. Учебные циклы повторяемы; одинаковое состояние отзывов не создаёт дубликатов. В настройках есть переключатель локального обучения.

`GET /api/soul/academy`, `POST /api/soul/academy/enabled`.

## 4. Устойчивая личность

`persona_continuity.py` связывает утверждённые пользователем предпочтения общения, биографические записи и историю разговоров. Внутренняя консолидация фиксирует только статистику и изменения, не дублирует приватные тексты в дневниках. Защищённые ценности из `soul/personality.json` **не изменяются**. Манера речи настраивается только на основании подтверждённых записей и обратной связи. «Эмоциональная модель» — программный регулятор тона, **не настоящие человеческие чувства**.

`GET /api/soul/character` выдаёт подтверждённые привычки, источники, историю взаимодействий и осторожно помеченное состояние.

## 5. Когнитивный центр и нагрузка

Существующая SQLite-очередь `maintenance.py` расширена: проверка целостности, слои памяти, векторные связи, качество, уроки, автоматические резервные копии, локальный FTS5, Академия, непрерывность характера и проверка сохранённых снимков. Каждая итерация запускает **не более одного ограниченного задания**; при активном чате оно откладывается. Показатель `over_budget` фиксирует превышение по факту, не гарантирует жёсткое прерывание CPU. Фон **не вызывает облачные LLM/embeddings**.

## 6. Мозг для десятков тысяч воспоминаний

Для маленькой базы (до 2400 записей) сохранён предыдущий граф. При большем объёме автоматически включается новая многоуровневая карта `brain_atlas.py` и `ui/atlas_view.ts`:

- **Обзор:** восемь типов секторов с реальным количеством одобренных воспоминаний.
- **Кластеры:** реальные группы по 256 ID, с пагинацией до 240 кластеров на страницу.
- **Соты:** до 160 реальных записей в выбранной группе и действительные связи между ними.
- Нажатие углубляет карту, двойной щелчок возвращает обзор; колесо масштабирует, перетаскивание перемещает, Esc возвращает предыдущий уровень. Есть отсечение за пределами Canvas и уменьшение движения для соответствующей настройки ОС.

`GET /api/soul/atlas?level=overview`, затем `level=clusters&sector=0` и `level=nodes&sector=0&bucket=123`. Сервер не выгружает сразу всю базу. Кластер — агрегат реальных записей, а не самостоятельное воспоминание.

**Ограничение:** тест с 20 000 синтетических записей проверяет структуру, ограничение размера ответов и индексацию. Плавность при 50–100 тысячах узлов на вашем ноутбуке требует отдельного браузерного тестирования. Отображение всех сот одновременно сознательно не предусмотрено.

## 7. Защита памяти

Копии по-прежнему создаются штатным SQLite Backup API приблизительно каждые 5 часов, хранятся до 12 снимков. Новая `verify_snapshots` проверяет последние снимки **без записи в них** и обнаруживает повреждённые файлы. Если последняя резервная копия повреждена, очередная запись не откладывается до следующего срока. Никаких автоматических перезаписей работающей базы. Офлайн-восстановление через `python restore_memory.py --list` и `--restore ИМЯ --confirm` требует закрытого сервера, блокировки запуска, проверки целостности источника и создания страховочной копии текущей БД.

Вся SQLite, история, кэш эмбеддингов и резервные копии находятся в `data/` вне GitHub. **База не зашифрована**: защита от постороннего доступа обеспечивается настройками компьютера и накопителя. Облачная LLM получает только явно разрешённый контекст диалога и подтверждённые выбранные воспоминания.

## Проверка

На локальном ПК: `Tsukiyora.bat` → настройки → «Диагностика и сохранность», затем отдельно «Cloud.ru». При ошибке сохрани **только обезличенное сообщение**, не присылай ключ, SQLite, токены или личные диалоги в публичный GitHub.

В CI: `python -m unittest discover -s tests -v`, Python compileall, `node --check` двух JS-совместимых TypeScript-модулей, Windows BAT smoke test и Linux. Реальный Cloud.ru без пользовательского ключа не проверяется, даже при зелёном CI.
