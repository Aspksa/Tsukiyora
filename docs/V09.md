# Tsukiyora v0.9 — стабилизация, RAG и когнитивная карта 100 000+

**Технологии:** Python как единственный локальный API, SQLite (включая FTS5), HTML5 Canvas, CSS, JS-совместимый TypeScript. Без Docker, Ollama, локальных моделей и новых сторонних библиотек. `data/` и ключ Cloud.ru не публикуются в GitHub.

## 1. Диагностика

**Windows:** `Tsukiyora.bat --self-test` — тест переносимого запуска, который использует **временную SQLite**, не открывает браузер и не затрагивает пользовательскую память. Он проверяет присутствие обязательных файлов, загружаемость персонажа, целостность временной базы, основные элементы HTML. GitHub Actions запускает его на Windows вместе с Python-тестами и JS `node --check` на Windows/Linux.

**Cloud.ru:** Кнопка «Проверить Cloud.ru» в существующих настройках отправляет настоящие тестовые запросы только после ввода ключа пользователем. Возможны платные токены. Без ключа успешность реального сервиса **не подтверждается**. CI использует имитацию сервера, включая сетевые ошибки, поток SSE и embeddings. Прогон в GitHub Actions не является тестом на пользовательском ПК и не проверяет все клики в реальном браузере.

## 2. Многошаговый RAG

`rag_pipeline.py`: до трёх ограниченных текстовых проходов на основе FTS5 и подтверждённых воспоминаний, затем до двух шагов перехода по реальным связям `memory_links`. Кандидаты имеют ID, источник, ссылку `[Память #ID]`, оценку релевантности, признаки `possible_conflict`, `potentially_stale` (по времени последнего обновления) и `source_exists`. **Эти сигналы не доказывают истинность:** старые данные могут оставаться актуальными, а наличие ссылки не подтверждает текст. Источник не найден — запись помечается, но не удаляется автоматически.

Режим полностью локальный, не отправляет дополнительные вопросы в облако. В потоковом чате передаётся ограниченное число подобранных подтверждённых фактов; сама генерация по-прежнему использует выбранную LLM Cloud.ru. Векторный поиск остаётся отдельной возможностью и запускается только при пользовательском разрешении.

`POST /api/soul/rag` — тело `{"query":"ремонт фар Lexus","limit":12,"max_age_days":365}`.

## 3. SOUL ACADEMY 3.0

`academy_metrics.py` сравнивает последние 8 и предыдущие 8 **явных пользовательских оценок** в каждой категории: точность, краткость, ясность, источники. Результаты: `improving`, `stable`, `regressing` или `insufficient_evidence`; для достоверного сравнения требуется минимум по 4 оценки в каждом окне. Измеряется изменение **оценок пользователя**, а не объективной правильности модели. История сохраняется в SQLite без дублирования идентичных контрольных срезов.

Безопасные стратегии остаются фиксированным списком; запрещены переписывание кода, автономное переобучение весов модели и подмена защищённого характера. Переключатель SOUL ACADEMY в настройках сохраняется.

`GET /api/soul/academy/metrics`.

## 4. Биография и непрерывный характер

`persona_continuity.py` добавляет датированную хронологию подтверждённых событий, привычек, биографии и записей журнала. Доступны источники и число исправлений, без вымышленных деталей истории отношений или настоящих эмоций. Защищённое ядро `soul/personality.json` не изменяется.

`GET /api/soul/character/timeline`.

## 5. Иерархический мозг

Для больших баз действуют уровни: **обзор 8 секторов → области по 8192 ID → кластеры по 256 ID → до 160 реальных сот**. Пользователь нажимает область или кластер для детализации, Esc — назад, колесо — масштаб, перетаскивание — перемещение. Сервер загружает только выбранный уровень. Области и кластеры — агрегаты фактов, а не искусственные воспоминания. Навигация и отрисовка используют ограниченные порции Canvas.

Маршруты:
- `GET /api/soul/atlas?level=overview`
- `GET /api/soul/atlas?level=regions&sector=0`
- `GET /api/soul/atlas?level=clusters&sector=0&region=5`
- `GET /api/soul/atlas?level=nodes&sector=0&bucket=157`

**Масштабируемость:** CI тестирует распределение более 100 000 синтетических записей на уровни и ограничение размера ответа. Это не означает, что реально проверена плавность на конкретном ноутбуке; потребуется визуальная проверка.

## 6. SQLite PRO

`migration_guard.py` до обновления уже существующей базы создаёт резервную копию, проверяет `PRAGMA quick_check`, отказывается открывать более новую неизвестную схему, затем фиксирует версию 9. Фоновая задача проверяет целостность, наличие индекса FTS5, пропуски и дубликаты производного индекса, ключи связей, но не удаляет факты. Новые таблицы создаются `CREATE TABLE IF NOT EXISTS`, схема и история бесед сохраняются.

**Пробное восстановление:** в настройках выбери резервную копию и нажми «Тест восстановления». `reliability.py` разворачивает её во **временную SQLite**, проверяет целостность и наличие истории, после чего удаляет временный файл. Рабочая база не изменяется. Для настоящего восстановления используй предыдущую офлайн-команду после закрытия BAT:

```powershell
python restore_memory.py --list
python restore_memory.py --restore ИМЯ_КОПИИ.sqlite3 --confirm
```

Автоматические снимки продолжают создаваться приблизительно раз в 5 часов (хранится до 12). Все снимки содержат личную историю без шифрования, поэтому защищай свой компьютер и накопитель.

## Контроль качества

```powershell
python -m unittest discover -s tests -v
python launcher.py --self-test
```

GitHub CI выполняет тесты на Windows и Linux и отдельно запускает Windows BAT. Успешный тест должен сопровождаться локальной проверкой Cloud.ru, embeddings, потоковых ответов и кликов пользователя в браузере на его ПК.

**Главный принцип:** Цукиёра может сравнивать собственные ответы с оценками и проверять источники, но не заявляет о сознании, настоящих чувствах или достоверности непроверенных сведений.
