# Tsukiyora v1.0 — локальная надёжность и единый интерфейс

Сохраняется исходный стек: **Python — единственный API, SQLite — единственная локальная БД, HTML5 Canvas + CSS + JS-совместимый TypeScript**. Без Docker, Ollama, системных сервисов, новых сторонних Python/npm-библиотек. Программа работает из папки проекта; ключ Cloud.ru остаётся в оперативной памяти Python.

## 1. Диагностика и стабилизация

`Tsukiyora.bat --self-test` проверяет переносимый запуск Windows на временной базе, не запускает браузер, не обращается к настоящему Cloud.ru. `python -m unittest discover -s tests -v` запускает регрессионные тесты. CI GitHub Actions выполняет Python и проверку синтаксиса браузерных модулей на Windows и Linux, включая BAT smoke на Windows.

В настройках доступна локальная диагностика: БД, миграции, целостность копий, видимость UI-элементов, статистика потока/очереди. **Это не настоящий браузерный end-to-end тест**. Проверка выбора моделей, SSE и embeddings с реальным ключом выполняется только вручную в разделе Cloud.ru; может расходовать токены. Все тесты CI мокируют внешний API. Запуск на компьютере пользователя остаётся непроверенным без его участия.

## 2. RAG 4.0

`rag_fusion.py` объединяет до трёх текстовых проходов FTS5, связи между воспоминаниями (до двух дополнительных шагов графа), биографические записи и **только заранее вычисленные и сохранённые embeddings**. Результаты имеют `[Память #ID]`, источник, каналы поиска, сигналы сомнений/противоречий и степень *поддержки поиска*. Наличие записи или высокая поисковая оценка **не гарантируют истинность факта**.

Облачных запросов при вызове нового RAG нет — даже если запрос отсутствует в кэше embeddings. Текст в Cloud.ru для embeddings отправляется только через уже существующие явно подтверждаемые операции. В чате устранено дополнительное скрытое облачное ранжирование. Сам ответ чата по-прежнему генерируется выбранной облачной моделью.

`POST /api/soul/rag4` с `{"query":"ремонт фар Lexus","limit":12}`. При разрешённой в сеансе векторной памяти поиск может дополниться закэшированными векторами. При промахе кэша вернётся `vector_cache: cache_miss` без облачного запроса.

## 3. SOUL ACADEMY 4.0

`academy_experiments.py` добавляет два **фиксированных, безопасных** способа организации ответа: «объяснять по шагам» и «сначала краткий ответ». Назначение стратегии стабильно в пределах диалога; сами варианты **не меняют защищённый характер**. Только явные оценки полезности пользователя формируют сравнение. Необходим минимум по восемь оценённых ответов для каждого варианта, и даже после него показана наблюдаемая разница, **не причинное доказательство** превосходства стратегии.

Сохраняются учебные цели, контроль регрессий и накопление опыта из предыдущих версий. Переключатель «Разрешить локальное обучение по оценкам» действует и для экспериментов. Без переобучения весов LLM, саморедактирования кода или произвольных несанкционированных промптов.

`GET /api/soul/academy/experiments`.

## 4. Личность и биография

Сохраняются подтверждённые источниками сведения, манера общения, хронология разговоров и версия исправлений. Цукиёра адаптирует **способ подачи ответа**, а не ключевые ценности персонажа `soul/personality.json`. Выводимые показатели характера — программная модель, **не реальные человеческие эмоции**. Новые уроки записываются только после явной обратной связи.

## 5. Мозг 1 000 000+

Сохраняются серверные уровни: обзор восьми секторов → области по 8192 ID → кластеры по 256 ID → максимум 160 реальных сот в одном запросе. Клавиатура, колесо мыши и перетаскивание управляют картой. Добавлен прямой поиск воспоминания по ID (`GET /api/soul/atlas?level=locate&id=1000003`) с переходом к нужному кластеру по индексу SQLite. Canvas регулирует частоту перерисовки в зависимости от измеренной стоимости кадра; показанная цель FPS **не равна измеренной фактической частоте на каждом ПК**.

CI проверяет адресацию ID в миллионном диапазоне и прежний тест на 100 000+ фактических записей. **Плавность на физическом компьютере с миллионом фактов не заявляется проверенной**. Индексация и пропускная способность на реальных файлах требуют отдельного нагрузочного испытания.

## 6. PRO+ сохранность SQLite

Прежние предмиграционные снимки, защита версии схемы, аудит индекса/связей и репетиция восстановления в отдельную временную SQLite сохранены. Ручное и фоновое резервное копирование теперь сериализованы внутри процесса Python; рабочая БД не заменяется при репетиции. Проверяются сохранность истории и отсутствие повреждённых копий. Восстановление настоящей БД — строго офлайн после остановки BAT.

```powershell
python restore_memory.py --list
python restore_memory.py --restore ИМЯ_КОПИИ.sqlite3 --confirm
```

## 7. Контроль расходов и приватности Cloud.ru

Новый `resource_guard.py` использует атомарные транзакции SQLite для суточных лимитов запросов чата (по умолчанию 100), embeddings (120) и общего ограничения в минуту (10). Лимиты настраиваются локально; при исчерпании запрос к провайдеру не начинается. Все попытки считаются **до HTTP**, поэтому лимит является защитным и не означает фактическое списание токенов. Подлинные токены/суммы Cloud.ru эти счётчики не измеряют.

Журнал сбоев хранит только категории (`cloud_failure`, `quota`, `sqlite` и т. п.) без текста сообщений, API-ключей и трассировок. Данные SQLite, embeddings и резервные копии не зашифрованы — защити диск/ПК и не публикуй папку `data/`.

`GET /api/system/cloud-budget`, `POST /api/system/cloud-budget` с `{"chat_per_day":100,"embeddings_per_day":120,"per_minute":10}`.

## 8. Дизайн

Чёрно-золотая минималистичная страница с левой интерактивной картой и правым чатом, без дополнительных страниц/вкладок. Настройки раскрывают только нужные панели, виден прогресс Академии, лимиты API, данные резервных копий. Уточнены шрифтовая иерархия, фокус клавиатуры, мобильная компоновка, поддержка уменьшения анимаций. CSS/Canvas работают без сетевых ассетов.

**Первый реальный запуск:** скачать `main`, открыть `Tsukiyora.bat`, проверить Cloud.ru и кнопки на своём ПК. Ошибки можно прислать обезличенно — без ключа, токенов и содержимого личной базы.
