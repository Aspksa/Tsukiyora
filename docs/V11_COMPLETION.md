# Tsukiyora — закрытие пробелов требований v1.1 поверх v1.2

Исходный PR v1.1 (#11) **уже был слит** и поверх него слит v1.2 (#12). Этот дополнительный патч не откатывает версии, а завершает два ранее недостаточно реализованных пункта списка: **семантическое объединение без потерь** и **поиск/сводки старой истории**.

## Память диалогов PRO

- `conversation_memory.py` создаёт локальный SQLite FTS5 с триггерами для новых, изменённых или удалённых сообщений. При первом включении индекса выполняется построение по **уже существующей** истории. Если FTS5 недоступен, поиск использует ограниченный локальный текстовый режим.
- В правом чате раскрывается небольшая панель «История · поиск и сводка»: поиск по **всем** сохранённым сообщениям (а не только 30 последним диалогам), постраничная навигация, открытие найденного диалога. Результат содержит ID сообщения, роль, название диалога и существующий фрагмент.
- Кнопка «Сводка текущего диалога» работает начиная с 12 сообщений. Вместо недостоверного автоматического пересказа она показывает **локальный экстрактивный конспект** из начальных и последних сообщений с `[Сообщение #ID]`. Он хранится в локальной SQLite и обновляется при поступлении новых сообщений. Это не генерация и не самостоятельное понимание содержания.
- Фоновая задача в существующей очереди обновляет до 4 недавних длительных диалогов за цикл, когда чат свободен. Не добавлены системные службы и облачные вызовы.
- API: `GET /api/memory/history/search?query=...&limit=20&before_id=N`, `GET /api/memory/history/recap?conversation_id=...`, `GET /api/memory/history/health`.

## Семантическая память 2.0

- Сохраняются обнаружение подозрительных смысловых дублей и противоречий, история исправлений и уже закэшированные векторы предыдущих версий.
- Новые `semantic_groups.py` и кнопка «Связать похожие» позволяют **после явного подтверждения** отметить две активные записи как эквивалентные, если их тип совпадает и нет признака явного противоречия.
- Никаких автоматических удалений и физических слияний строк. Все оригиналы, исходные источники и `memory_revisions` остаются. После исправления одного факта подтверждённая связь помечается устаревшей, пока пользователь её не перепроверит. В журнале сохраняются действия подтверждения/отмены.
- API: `GET /api/soul/semantic/groups`, `POST /api/soul/semantic/link` и `POST /api/soul/semantic/unlink` (JSON с `left_id`, `right_id`, `confirmed:true`).
- Вывод качества — эвристика; семантическая близость не доказывает истинности, подтверждение эквивалентности не является юридическим или фактическим заключением.

## Совместимость и безопасность

- SQLite `PRAGMA user_version=13`, до обновления существующей базы создаётся локальная согласованная копия. Создаются только новые индекс/триггеры/таблицы — исходные записи не удаляются.
- Сохраняются Python единственный API, SQLite единственная БД, JS-совместимый TypeScript/HTML5 Canvas/CSS. Без новых библиотек, Docker/Ollama/локальных LLM.
- GitHub CI запускает существующие unit/API/Cloud.ru-моки, проверки отмены streaming, Windows BAT smoke и нагрузочный тест на **миллионе фактических строк SQLite** на Windows/Linux. Новые тесты покрывают пути с кириллицей и пробелами, миграцию, индекс FTS5, поиск из старого диалога, цитаты, конкурентную запись, подтверждение/отмену смысловых связей и same-origin защиту.
- **Не утверждается:** реальный Cloud.ru с личным ключом, работа всех кликов в браузере пользователя или FPS на его ПК. Реальные услуги Cloud.ru доступны только по отдельному действию в настройках. Личные данные остаются в локальном `data/`; защищай диск средствами Windows.
