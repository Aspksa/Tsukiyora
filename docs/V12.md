# Tsukiyora v1.2 — RAG 6.0, Академия 6.0 и SOUL NEXUS

**Базовая архитектура неизменна:** Python 3.10+ — единственный API, SQLite — единственная локальная база, браузерные JS-совместимые TypeScript/HTML5 Canvas/CSS. Без Docker, Ollama, локальных LLM, новых npm/Python-зависимостей и системных служб. Вся информация остаётся локально в `data/`; ключ Cloud.ru — только в памяти процесса.

## 1. Стабильность и диагностика

GitHub CI запускает unit/API тесты Windows+Linux, Python compileall, `node --check`, Windows `Tsukiyora.bat --self-test`, миллионный SQLite тест. Проверяются история, SQLite, обработка ошибок, поток SSE, отмена генерации и имитации Cloud.ru/embeddings. Самотест использует временную БД; не открывает браузер.

**Ограничение:** это не тест реального Cloud.ru, всех браузерных нажатий или ноутбука пользователя. Ручная «Проверить Cloud.ru» может расходовать реальные токены; для неё требуется ключ пользователя. Данные CI не позволяют утверждать, что фактический API провайдера доступен.

## 2. RAG 6.0: документы, цитаты, условия договоров

Поиск по подтверждённой памяти, графу и только разрешённому кэшу embeddings дополнен явно импортированными локальными документами. Файлы: **UTF-8 TXT, Markdown, DOCX и простые текстовые PDF до 1 МБ**. Python использует стандартные `zipfile`, `xml.etree`, `zlib`; документы читаются и разбиваются на ограниченные фрагменты в SQLite. Импорт требует выбора файла и отдельного подтверждения; исходные бинарные файлы не сохраняются, сохраняется **извлечённый текст**.

- DOCX: читается основное содержимое `word/document.xml`; макросы и внешние связи не выполняются.
- PDF: поддерживаются базовые машиночитаемые потоки `Tj/TJ`, в том числе `FlateDecode` и некоторые кодировки. Сложные шрифты, расположение колонок, зашифрованные документы, сканы и OCR **не поддерживаются**. При невозможности извлечения сообщается об ошибке, а не о ложном успехе.
- Договоры: локальные регулярные правила выделяют **кандидаты дат, сумм, обязательств и формулировок**, привязанные к реальным `[Документ #ID, фрагмент N]`. Разные суммы в разных текстах помечаются как **различие для проверки**, не как доказанное противоречие.
- Проверка ответов устанавливает **существование** цитируемого источника и признаки возможных противоречий. Это не юридическое заключение, не проверка фактической истинности и не полноценный семантический парсер PDF.

**Приватность:** по умолчанию документы и их содержимое не отправляются в Cloud.ru. Отдельный переключатель «Разрешить Cloud.ru получать найденные фрагменты документов» действует **только в текущем сеансе**, после выключения сервера сбрасывается. Фоновое обслуживание не вызывает Cloud.ru.

API: `POST /api/soul/documents/import-binary` (JSON `name`, `base64`, `confirmed:true`, до 1 МБ бинарного файла); `GET /api/soul/contracts/insights?id=N`; прежние `/api/soul/evidence`, `/api/soul/documents` и `/api/cloud/documents/consent` остаются.

## 3. SOUL ACADEMY 6.0

Сохраняются учебные цели и A/B форматы из v1.1. Новое: если необязательный стиль получает **не менее 8 явных оценок** и **не более 25% положительных**, он автоматически приостанавливается и не добавляется в дальнейшие prompts; отзывы не стираются. Пользователь может вернуть стиль вручную в настройках. Ключевые защищённые черты личности неизменны.

Добавлены четыре контрольных вопроса по источникам, точности, ясности и краткости. Пользователь может вставить проверяемый ответ в настройках. Локальная проверка измеряет ограниченные правила/ключевые слова; **это не объективная оценка качества модели и не автоматический экзамен облачной LLM**. Не происходит изменения весов или исходного кода.

API: `GET /api/soul/academy/rollback`, `POST /api/soul/academy/rollback/resume`, `GET /api/soul/academy/practice`, `POST /api/soul/academy/practice/evaluate`.

## 4. Биографическая память

Остаются хронология, источники, подтверждённые предпочтения и ревизии. Новый `GET /api/soul/persona/links` возвращает **только существующие связи SQLite между одобренными записями биографии, событий и предпочтений**. Не выдумывает людей, отношения и эмоции. Ядро `soul/personality.json` не изменяется.

## 5. Мозг 1 000 000 PRO

Новый `atlas_materializer.py` строит из существующих утверждённых записей **материализованные счётчики SQLite** по секторам/областям, поддерживаемые триггерами INSERT/UPDATE/DELETE. Это производный кэш: может быть пересобран без потери исходных фактов. `BrainAtlas` использует его в обзоре и загрузке областей, сохраняя ограниченную выдачу реальных сот. Поиск ID и групп, колесо масштаба и виртуализация Canvas сохраняются.

`scripts/test_million_atlas.py` заполняет **один миллион реальных строк SQLite**, создаёт/проверяет индекс агрегатов, измеряет время запросов и подтверждает ограниченный объём ответов. **FPS браузера на пользовательском ПК CI не измеряет**. В интерфейсе выводится наблюдаемая частота кадров запущенной страницы, но это не гарантия производительности на другом оборудовании.

В новом дизайне SOUL NEXUS усилены почти чёрный фон, золотые соты и линии **только существующих** связей. Свечение при изменении фактического состояния/навигации, а не демонстрационные фиктивные события. Минимум новых контролов; всё внутри существующей страницы настроек.

## 6. Фоновый цикл 2.0

Локальная SQLite-очередь с восстановлением после сбоя теперь включает проверки материализованного индекса, ограниченную консолидацию и откат безопасных форматов ответа, пассивную диагностику WAL/ключей. Обслуживание откладывается, если активен чат. Один цикл запускает максимум одну задачу, без фоновых облачных запросов. **«24/7» означает только время, когда запущен Python-процесс; при выключенном компьютере программа не работает.**

## 7. Память без потерь 2.0

Новые резервные копии SQLite снабжаются **SHA‑256**, хранящимся в локальной таблице метаданных. Перед пробным восстановлением известная контрольная сумма и размер проверяются. Копии старых версий без хеша помечаются `legacy_unrecorded`; их можно проверить по SQLite-структуре, но нельзя выдавать за проверенные по SHA‑256. При повреждении не производится автоматическое восстановление или удаление единственной рабочей копии.

Новая диагностика `GET /api/system/wal` выполняет пассивный WAL checkpoint, проверку внешних ключей и `PRAGMA quick_check`. Регулярные снимки приблизительно раз в 5 часов, хранится до 12, восстановление **только офлайн после закрытия BAT**:

```powershell
python restore_memory.py --list
python restore_memory.py --restore ИМЯ_КОПИИ.sqlite3 --confirm
```

Версия SQLite-схемы — 12; до миграции существующей базы создаётся локальная резервная копия. **Факты, история и резервы не шифруются; защищай накопитель средствами Windows**.

## Как проверить локально

Скачай актуальный `main`, запусти `Tsukiyora.bat --self-test` для автономной проверки, затем обычный `Tsukiyora.bat`. В настройках проверь документы, договорные цитаты, контрольные вопросы, состояние SQLite и карту. Реальный Cloud.ru и взаимодействие с браузером проверь отдельно с собственным ключом и без публикации секретов/базы.

CI: `python -m unittest discover -s tests -v`; `python scripts/test_million_atlas.py`. Результат нагрузочного теста описывает **тестовый компьютер GitHub**, не пользовательский ноутбук.
